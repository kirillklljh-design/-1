# Размещение на Vercel и подключение кабинета

## 1. Сразу открыть сайт на Vercel

Импортируйте репозиторий https://github.com/kirillklljh-design/-1, ветка `main`.

| Поле Vercel           | Значение                                                     |
| --------------------- | ------------------------------------------------------------ |
| Project Name          | `tehnika-rent` или другое свободное имя                      |
| Root Directory        | `./`                                                         |
| Application Preset    | `Next.js`                                                    |
| Build Command         | `npm run build` (задано в vercel.json)                       |
| Install Command       | `npm ci` (задано в vercel.json)                              |
| Output Directory      | стандартное значение Next.js, override выключен; **не dist** |
| Environment Variables | на первом шаге можно не задавать                             |

Нажмите Deploy. После статуса Ready нажмите Visit и скопируйте адрес `…vercel.app`. Точный домен назначает Vercel — заранее его выдумывать нельзя.

Если проект уже импортирован: откройте настройки Build and Development, проверьте Next.js и уберите старый override `dist`; затем выполните Redeploy последнего коммита. Если подключена Git-интеграция, push в main обычно запускает сборку автоматически.

До подключения Supabase каталог, фотографии, расчёт и подготовка заявки в Telegram работают. Добавление и редактирование карточек станут доступны после следующих шагов.

## 2. Создать Supabase

1. Войдите на https://supabase.com/dashboard и создайте отдельный проект для этого сайта. Выберите подходящий тариф самостоятельно; приложение не требует покупки платной подписки для первоначальной проверки. Пароль базы храните у себя.
2. Откройте SQL Editor. Вставьте и выполните **один раз на новой базе** весь файл `supabase/schema.sql` из репозитория. Затем выполните `supabase/migrations/20261018_minimum_two_hours.sql`: он устанавливает минимальную смену 2 часа для всех машин. На уже настроенной базе выполняйте только новую миграцию, без повторного запуска schema.sql.
3. В Authentication → Providers / Sign In Settings оставьте Email/Password и отключите регистрацию новых пользователей (Allow new users to sign up). В интерфейсе сайта регистрации тоже нет.
4. В Authentication → Users → Add user создайте владельца с его email и надёжным паролем. Для пользователя, которого вы создаёте вручную, подтвердите email через опцию Auto Confirm. Пароль в код или чат не вставляйте.
5. Скопируйте UUID созданного пользователя. В SQL Editor выполните, подставив UUID вместо заглушки:

```sql
insert into public.site_owners (user_id)
values ('ВСТАВЬТЕ-UUID-ПОЛЬЗОВАТЕЛЯ')
on conflict do nothing;
```

Доступ назначается по UUID, не по тексту email из формы. Другие зарегистрированные пользователи прав владельца не получают.

## 3. Подключить проект к Vercel

В Supabase откройте Connect / API Keys и скопируйте Project URL и Publishable key. В Vercel → проект → Settings → Environment Variables добавьте:

```dotenv
NEXT_PUBLIC_SUPABASE_URL=https://ВАШ-ПРОЕКТ.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=ВАШ-PUBLISHABLE-KEY
```

Это публичные параметры подключения. **Не используйте service_role, secret key или пароль базы.** Роль владельца и правила доступа проверяются сервером и PostgreSQL.

Задайте параметры для Production и Preview, если обе среды должны использовать этот проект. Для работы с реальными клиентскими данными лучше выделять Preview отдельный проект Supabase. После добавления параметров обязательно нажмите Redeploy — Next.js включает публичные параметры в клиентскую сборку.

Для локальной проверки скопируйте `.env.example` в `.env.local` и заполните эти же два значения. `.env.local` игнорируется Git.

## 4. Проверить кабинет

1. Откройте адрес Vercel → «Панель владельца» в подвале.
2. Введите email и пароль созданного владельца.
3. Добавьте машину с фото, ценой и минимальной сменой; нажмите «Сохранить карточку».
4. Откройте сайт в другом окне и проверьте карточку. Затем проверьте редактирование, скрытие, восстановление и удаление тестовой карточки.
5. Нажмите «Выйти» и убедитесь, что вход снова требуется.

Если вход проходит, но нет доступа: проверьте UUID в `site_owners`. Если каталог сообщает об ошибке: проверьте выполнение SQL и оба параметра окружения. Если фото не загружается: проверьте bucket `machine-photos` и политики из schema.sql, формат JPG/PNG/WebP и размер до 5 МБ. Новый файл отправляется напрямую в Supabase, а не целиком через функцию Vercel.

## 5. Настройки конкретной компании

В `src/config.ts` меняем логотип, название, город, Telegram и три тарифа доставки. Владелец этих настроек не видит. Telegram задаётся username без @. Пока значение пустое, кнопки показывают уведомление. `null` в цене доставки означает «уточняется отдельно», `0` — бесплатную доставку.

Счётчик техники берётся из каталога. Фотографии исходных карточек встроены в сайт, новые фото владельца хранятся в Supabase. Для каждого следующего клиента используйте новые проекты Vercel/Supabase и отдельно назначайте владельца.
