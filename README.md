# Сайт аренды спецтехники

Обычный Next.js 16 / React, готовый к размещению на Vercel. Фотографии первого экрана и четырёх машин взяты из предоставленных скриншотов. Логотип оставлен текстом «Укажите логотип».

## Запуск

Нужен Node.js >=22.13 и npm. Команды выполняются из корня проекта:

```sh
npm ci
npm run dev -- --port 3000
```

Откройте http://127.0.0.1:3000/. Для production-проверки:

```sh
npm run build
npm start -- --port 3000
```

Без переменных Supabase работают страница, четыре исходные карточки и калькулятор. Кабинет честно показывает «ещё не подключён», записи не имитируются. Если Supabase настроен, но недоступен, сайт сообщает об ошибке чтения, а не подменяет реальные данные демонстрационными.

## Публикация

Пошаговое руководство: [DEPLOYMENT.md](DEPLOYMENT.md). Vercel использует `vercel.json`, preset Next.js, команды `npm ci` и `npm run build`. Стандартный выход Next.js — `.next`. `dist` больше не используется.

База PostgreSQL, фотографии и вход владельца — Supabase. Нужны только Project URL и Publishable key из `.env.example`. Ключ service_role не используется. Никогда не добавляйте реальные `.env.local` и пароли в Git.

## Что где находится

- `app/`: страницы, защищённые API и маршруты входа/выхода.
- `src/`: клиентский интерфейс, калькулятор, конфигурация компании, адаптер Supabase.
- `supabase/schema.sql`: однократная настройка новой базы, RLS и хранилища, четыре исходные карточки.
- `public/assets/photos/`: фотографии из слайдов в SVG-областях отображения; исходные PNG встроены без генерации или ретуши.
- `tests/`: расчёт, защита запросов, политики PostgreSQL и браузерные сценарии.

Оформление, Telegram, город и три тарифа доставки меняем мы в `src/config.ts`. Владелец управляет только карточками: фото, названием, описанием, ценой за час, минимумом часов, скрытием и удалением. Статусов свободна/занята нет. Нет верхнего ограничения часов аренды.

Изначальные фотографии имеют разрешение скриншотов; мини-экскаватор взят из кабинета, где нет плашки «Выбрано». Для извлечения из исходных файлов: `node scripts/extract-slide-photos.mjs <папка-со-скриншотами>`. Для лучшего качества впоследствии замените SVG обычными JPG/WebP и обновите ссылки в `src/photo.ts` и первом экране.

## Проверки

```sh
npm test
node node_modules/typescript/bin/tsc --noEmit
npm run build
```

`npm test` включает проверку правил RLS в настоящем движке PostgreSQL через PGlite: анонимные посетители видят только опубликованные машины, другой пользователь не может изменять данные или назначить себя владельцем.

Браузерные проверки требуют Playwright и установленного Edge/Chromium. Если Playwright установлен вне проекта, задайте `PLAYWRIGHT_MODULE` абсолютным путём к `playwright/index.mjs`.

```sh
# С работающим production-сервером на 127.0.0.1:5173 без Supabase:
node tests/browser.mjs
# Сам поднимает изолированный HTTP-имитатор Supabase и Next dev на 5174:
node tests/owner-integration.mjs
```

Вторая проверка тестирует cookies, доступ, API, прямую загрузку фото и интерфейс на локальном имитаторе. Она не подтверждает подключение настоящего облачного проекта. Снимки и отчёты: `outputs/vercel-qa/`, результаты — `QA.md`.

## Данные и безопасность

Роль владельца назначается по UUID пользователя в `site_owners`, только через SQL Editor. Публичной регистрации в интерфейсе нет; отключите регистрацию в Supabase. Cookies обновляются в `proxy.ts`; сервер проверяет пользователя через Auth, а право записи — RPC и политики RLS. Заголовки старой платформы Sites не дают доступа.

Фото загружаются напрямую в Supabase по подписанному URL, до 5 МБ, JPG/PNG/WebP. Это позволяет обходить ограничение Vercel на размер тела запроса без отключения защиты. Подписанный URL выдаётся только владельцу после проверки Origin. Скрытие карточки не делает само фото секретным: фотографические материалы публичны.

Для нового клиента создавайте отдельный проект Supabase и отдельный проект Vercel. Не переносите клиентские данные и роль владельца между проектами. Каталог `drizzle/` сохранён как неизменяемая история прошлой версии D1, в новой сборке не применяется. Старая опубликованная версия Sites автоматически не обновляется.
